figspec-pilot

Figma design → EARS spec + vitest tests, via MCP and a local Ollama model.
MCP server Ollama gemma3:4b EARS grammar vitest

Four MCP tools, one pipeline

  figma_get_file     fetch a Figma file as a depth-capped node tree
  extract_spec       node tree → EARS-formatted requirements (LLM)
  lint_spec          6 deterministic rules over the EARS output
  generate_tests     EARS → vitest skeleton, one it() per requirement
Stdio transport. Token never leaves the process. No LLM API key required.

Run the end-to-end demo

$ npm run demo

Seven design decisions, each as a Nygard ADR

ADR-0001 — Why an MCP server, not a Figma plugin
ADR-0002 — Use stdio transport, defer HTTP / SSE
ADR-0003 — Figma API rate-limit and token-handling strategy
ADR-0004 — Use EARS, not Gherkin, as the requirements grammar

ADR-0005 — Lint rule selection — six deterministic rules over EARS
ADR-0006 — Generate vitest skeletons, not Jest / node:test / AVA
ADR-0007 — Ollama as the default LLM backend, Claude as opt-in
Each ADR has Context / Decision / Consequences / Tradeoffs sections.

正直な開示 — 現行AI技術で 原理的に 解決不可な部分

  - AIの幻覚 — 業界全体の未解決問題
    Claude/GPT/Gemini も同様。 自動検査 と 人間レビューの 二段防御で 対処。
  - Figma API 回数制限 — Figma 社のサーバー側制約
    10-20 回/分は 全 Figma クライアント共通。 キャッシュ再利用が 唯一の解。
  - LLM の物理上限 — モデルサイズと 文脈長
    gemma3:4b の精度と 入れ子 5 階層が 現状の天井。 大型モデル投入で 解除可。
  - stdio 通信のみ — v0.1 の段階的リリース範囲
    HTTP/SSE 対応は 顧客要望に応じて 次版で 追加。
